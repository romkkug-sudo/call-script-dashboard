# 架電トークダッシュボード（call-script-dashboard）

テレアポ（架電）のトークスクリプトを管理し、**どのトークが通りやすいか**を記録・比較するためのWebアプリです。
実際に架電業務をする中で「トークの良し悪しが感覚でしか分からない」「改善しても前の版と比べられない」という課題を感じ、
ブラウザだけで動くHTMLのプロトタイプを作ったあと、Spring Boot + DB の構成に作り直しました。

> 公開用のため、初期データのトークはすべて架空の会社「サンプル株式会社」を想定したダミーです。

## できること

- **3つのフェーズ別にトークを管理**：受付突破 → ごあいさつ → クロージング、それぞれ独立して成功率を記録
- **架電結果をワンクリックで記録**：通話中でもマウスだけで操作できる画面構成
- **NG理由の集計**：「今は必要ない」「予算がない」など6種類から選択し、断られ方の傾向を把握
- **トークの版管理**：使用中のトークを編集すると、元の版は「お蔵入り」にして新しい版を発行（前の版との成績を比較できる）
- **切り返しトーク集・業種別トーク**：よくある断り文句への対応例と、業種ごとの言い回しを初期データとして用意
- **1日の目標（コール数・アポ数）とKPI表示**

## 工夫した点

- **「誰が使っても同じ成功率が出る」ことを目標に設計**：フェーズごとに成功・失敗を分けて記録し、どこで止まっているかを見える化
- **初期データの安全な追加**：初期トークはIDごとに「未登録のものだけ」追加するため、運用中にデータを足しても既存の記録を壊さない
- **テストを用意**：Service・Controller・結合テストを JUnit / Mockito で作成（全51件）

## 使用技術

| 分類 | 技術 |
|---|---|
| バックエンド | Java 21 / Spring Boot / Spring Data JPA（REST API） |
| DB | H2（ファイル保存。別途インストール不要） |
| フロントエンド | HTML / CSS / JavaScript |
| テスト | JUnit 5 / Mockito / MockMvc |

## 起動方法

```bash
./mvnw spring-boot:run
```

起動後、ブラウザで `http://localhost:8081` を開きます。
初回起動時に初期トークが自動で登録されます。データは `./data/` に保存され、再起動しても消えません。

## テスト

```bash
./mvnw test
```

## 主なAPI

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/phases` | フェーズ定義（受付突破／ごあいさつ／クロージング） |
| GET | `/api/ng-reasons` | NG理由の一覧 |
| GET | `/api/scripts?phase=xxx&includeArchived=bool` | トーク一覧 |
| POST | `/api/scripts` | トークの新規追加 |
| POST | `/api/scripts/{id}/revise` | トークの編集（新しい版を発行） |
| PATCH | `/api/scripts/{id}/archive` / `/restore` | お蔵入り・復活 |
| GET | `/api/logs` / `/api/logs?day=today` | 架電ログ（全期間／当日） |
| POST | `/api/logs` | 架電結果の記録 |
| DELETE | `/api/logs/{id}` | ログの取り消し |
| PATCH | `/api/logs/{id}/memo` | ログのメモ更新 |
